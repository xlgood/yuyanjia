## 四、回滚预案

1. **代码回滚**：`git log` 找到本次改动前的提交 → `git revert <commit>`（或 `git checkout <旧commit> -- 相关文件`）→ 重新 `npm run deploy`；
2. **数据回滚**：`migratePoints` 幂等可重跑（新版本）；若误跑旧版 50 爻迁移，重跑新版 `migratePoints` 即可覆盖修正；
3. **广告回调回滚**：若内层验签误杀合法回调，置 `AD_SSV_VERIFY_SIGN=false` 重新部署 `adRewardCallback` 即可（其余函数不受影响）。

## 五、常见问题

| 现象 | 处理 |
|------|------|
| `deploy.sh` 报某函数上传失败 | 按提示重试该函数；@cloudbase/cli 偶发 `ResourceInUse`，等 1 分钟重跑 |
| 存量用户分享还是 openid | 首次登录后 `inviteCode` 自动补发，重新进一次小程序即可 |
| 总榜排序异常 | 确认已建 `users.points` 索引且已部署新版（总榜按余额而非 totalPoints） |
| 周/月榜数值变小 | 属预期：本轮起签到/广告/补助不再计入榜分（净收益口径），`migratePoints` 重算后生效 |
| 仲裁发起提示冷却 | 属预期：24h 冷却对任意最近一次发起生效（含已结案），事务内 CAS 防并发绕过 |
| 榜单没有我的排名 | 正常：榜分 > 0 才上榜；`points` 为 0 或对弈不足 5 场不显示 |
