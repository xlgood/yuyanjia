## 三、P1 · 已确认缺陷

### P1-1 详情页倒计时切后台/切页后停止（✅ 本轮已修复）
- **现象**：详情页进入后台或跳到其它 tab 再返回，倒计时不再跳动（`onHide` 停了定时器但 `onShow` 未重启）。
- **修复**：`detail.js onShow` 增加 `this.startCountdown()`（commit 见报告末尾）。
- **影响**：截止/昭示倒计时显示停滞，用户可能误判时间。

## 四、P2 · 建议优化（按价值排序）

| # | 项 | 说明 | 建议 |
|---|---|---|---|
| P2-1 | 首页列表无倒计时/无「昭示中」剩余时间 | 详情有实时倒计时，首页仅静态截止时间 | 首页列表项加轻量倒计时（分钟级即可）或状态 chip 带剩余时长 |
| P2-2 | 空捕获静默（2 处） | `detail.js:156`（公断加载失败）、`profile.js:60`（PK 收件箱加载失败）`catch(()=>{})` | 失败时 toast 或静默可接受，建议至少 console.warn 便于排查 |
| P2-3 | task / shop / profile 页无显式加载/空态 | 均为静态/本地数据页，风险低 | 登录中给 loading 提示，避免「未登录」空白 |
| P2-4 | 倒计时 1s 轮询 setData 频率 | 每秒 setData 详情页（仅 countdownText 变化时），低端机可能有感 | 可改为 500ms 或分钟级+秒级混合；当前可接受 |
| P2-5 | 客服/反馈入口缺失 | 无客服会话、无反馈通道 | 提审阶段建议接入微信客服（open-type="contact"），同时是审核友好项 |
| P2-6 | 深色模式未适配 | 全部浅色 | 非必须；若做，WXSS 变量化成本高，建议二期 |
| P2-7 | api.js 无显式超时 | 云调用走默认超时 | 长链路（结算）场景可加超时兜底提示 |
| P2-8 | 敏感词黑名单覆盖有限 | 两处 SENSITIVE_WORDS（前端/云端）覆盖常见词，但可扩充（政经/地域黑等） | 建议接微信云开发 `security.msgSecCheck` 作为昵称/道号补充校验（提审加分） |
| P2-9 | avatar.wxs 与 constants.AVATARS 双维护 | 两处列表需手工保持一致（当前一致） | 加一条一致性校验进 `npm run check` |
| P2-10 | 首页热门阈值 hotThreshold 硬编码 | 配置项写在 config.js | 保留前端配置即可；运营期建议挪云端可调 |
| P2-11 | leaderboard 切 tab 无缓存刷新策略 | 每次切换重新拉取 | 可接受；数据量大后加本地缓存 |
