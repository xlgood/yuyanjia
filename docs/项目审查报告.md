## 二、必须修复（P1 · 功能/一致性）

### P1-1 昭示期两处默认值不一致（自动 5 小时 / 人工 2 小时）

同一个环境变量 `DISPUTE_WINDOW_HOURS` 在两个判定函数里缺省值不同：

- `cloudfunctions/resolver/index.js:12`：`|| 5`（自动判定 → 5 小时昭示）；
- `cloudfunctions/resolveMarket/index.js:4`：`|| 2`（人工判定 → 2 小时昭示）。

不配置该环境变量时，自动判定的事件给 5 小时异议窗口，人工判定的事件只给 2 小时，而 `config.js` / README / 部署清单都写「5 小时」。这直接影响公平性与用户体验一致性，必须统一。

建议：把权威默认值收敛进 `_shared/config.js`（或显式登记环境变量），两个函数保持一致，并同步所有文案。

### P1-2 mock 与云端口径/量级漂移

本地演示数据与线上不一致，会掩盖榜单 bug：

- `miniprogram/utils/mock-data.js:1515` 榜单 `total` 仍映射 `totalPoints`，云端 `getLeaderboard` / `rankSnapshot` 已改为 `points`（当前爻余额）；
- mock 种子用户 `u1~u10` 仍是旧 1/10 缩减前的 1000 量级（3200/45600 等），云端初始爻已是 100。

结论：活跃用户的登录/邀请经济（冒烟断言 100、110）一致，但**榜单演示数据未同步**。

### P1-3 文档大范围漂移

以下文档仍使用「能量 / 好友 / 1000 / 12 小时 / 5 小时」等旧口径，与当前「爻 / 道友 / 100 / 卦爻」不一致（旧产品名「预言大师 / 问卦局」已随本轮定名改为「预测卦局」）：

- `database/design.md`：`points` 初始 1000、`weekPoints/monthPoints` 描述为「获得能量」、`pkOpen` 描述为「好友」；
- `docs/开发方案.md`：大量「能量 / 好友 PK / 1000 能量 / Oracle」旧词（名称旧词已替换）；
- `docs/广告与变现说明.md`：整篇仍是「能量 / 看视频领能量」；
- `docs/prototype/preview.html`：早期蓝色原型残留（含「12 小时 + 能量」），已归档可忽略。

## 四、部署注意（触发器与双部署路径）

1. **触发器不会随 `npm run deploy` 自动同步**。标准入口 `scripts/deploy.sh` 使用 @cloudbase/cli，脚本明确「上传不同步 config.json，需控制台手工配置」。7 组触发器必须在云开发控制台逐一核对：
   - `lockMarkets` 每分钟 `0 * * * * * *`
   - `resolver` 每 10 分钟
   - `settleMarket` 每 10 分钟
   - `settleArbitration` 每 5 分钟
   - `myPks` 每 10 分钟
   - `rankSnapshot` 每天 **23:55**（先于 `resetPeriods` 00:00 清零，避免快照竞争）
   - `resetPeriods` 每周一 / 每月 1 日 00:00
2. **存在两条部署路径**：微信开发者工具 CLI（会带 `config.json` 上传触发器）与 `deploy.sh`（@cloudbase/cli，不带触发器）。混用易漏配，建议固化一条并写进部署清单。

## 五、影响用户体验

1. 昭示期 2h/5h 不一致（P1-1）直接造成用户体感不同；
2. 详情页信息密度仍偏高（判定标准 + 表态 + PK + 仲裁 + 开发面板），建议把「发起仲裁/PK」收进折叠区；
3. 爻经济缩减为 1/10 后的数值体验（初始 100、最低表态 10、签到 5、广告 10、破产补助 50）需产品确认吸引力，属经济平衡项；
4. 首页列表目前无轻量倒计时（详情页有，且已修复 onShow 重启倒计时停滞）。

## 六、影响上线 / 过审（需产品决策）

1. **「卦 / 爻 / 断卦 / 应验 / 问签 / 邀友论卦」的占卜化定位是当前最大过审风险**。微信对「封建迷信、占卜算命」类内容有明确限制。建议：
   - 类目明确选「娱乐-趣味测试/趣味百科」或「工具」，避开占卜/算命类目；
   - 提审素材弱化「预测/占卜」表述，避免「应验、预知、准确」等暗示真实预测能力的词；
   - 页脚加「仅供娱乐，不构成任何预测或投资建议」声明；
   - 这是产品合规决策，代码无法单独解决。
2. `APP_MODE=compliance` 仍是**纯前端视图开关**，云函数接口照常可用，只是视图层合规；
3. 「激励广告 → 爻 → 预测输赢 → 平台广告收益」组合的合规风险依旧存在，建议整体评估；
4. 后端敏感词表命中「下注/投注/赔率/赌博/博彩」等词（合规脚本判定后端可接受），风险低，追求最干净可连同注释清理。
