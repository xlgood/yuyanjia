### C4. 部署云函数（37 个目录，全部需部署）

开发者工具资源管理器 → 右键 `cloudfunctions` 下每个函数目录 →「上传并部署：云端安装依赖」。

> **一键脚本（推荐）**：仓库已内置 `scripts/deploy.sh`（基于 @cloudbase/cli，自动按需安装、不污染全局）：
>
> ```bash
> npm run deploy:login   # 首次：浏览器登录腾讯云（凭证存 ~/.cloudbase）
> npm run deploy         # 上传已改动函数（自动先跑 sync:common 同步公共配置）
> npm run deploy:all     # 首次部署全部函数（自动跳过 _shared 公共目录）
> ```
>
> **公共配置说明**：业务常量单一来源在 `cloudfunctions/_shared/config.js`，上传前 `sync:common` 会把
> 它物理拷贝为各消费函数的 `common-config.js`（CLI 打包不支持跨目录 require）。改常量后运行
> `npm run sync:common` 再上传；`npm run check` 会校验拷贝未漂移。
>
> 或用开发者工具 CLI（已实测可用）：
>
> ```bash
> /Applications/wechatwebdevtools.app/Contents/MacOS/cli cloud functions deploy \
>   --env <环境ID> \
>   --paths /绝对路径/cloudfunctions/<函数名> ... \
>   --appid <AppID> -r
> ```
>
> 注意：首次失败会在云端留下「Creating」空壳，等 1 分钟状态就绪后重跑即可。
> `resolver` 的 `adapters/` 子目录已内联进 `index.js`（CLI 打包不支持子目录，会报 EISDIR；

## D. 常见问题

| 现象 | 原因与处理 |
| --- | --- |
| 预览提示 AppID 是测试号 | 必须用真实 AppID 重新导入项目 |
| 云函数调用报 `FUNCTION_NOT_FOUND` / `-501000` | 函数未部署或未部署最新版，重新「上传并部署」 |
| 运营后台提示「无权限操作」 | `ADMIN_OPENIDS` 没填或填错；openid 以 `users` 集合 `_id` 为准 |
| AI 起草报「未配置 DeepSeek API Key」 | 环境变量 `DEEPSEEK_API_KEY` 未设置，或函数未重新部署 |
| 页面显示空白/报错 | 基础库版本过低：右上角「详情 → 本地设置 → 调试基础库」选 3.x |
| 提审被拒（若发生） | 切 `APP_MODE='compliance'` 再提审，并自查 `node scripts/check-compliance.js` |
