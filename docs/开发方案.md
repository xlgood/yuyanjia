## 1. 需求解读与产品定位

### 1.1 一句话定位

用「虚拟爻值」支撑的 YES/NO 热点预测（瓜分池模型），通过连胜荣誉与社交裂变形成传播闭环的微信小程序。

### 1.2 从文档提炼的核心机制

| 文档机制 | MVP 落地 |
| --- | --- |
| 瓜分池 Pari-mutuel | 表态时爻进入 YES/NO 单侧池；结算时正确方按投入占比瓜分总池：`R = A_user / P_winner × P_total` |
| 双向交易 | MVP 不做二级市场交易（一期简化：每场每用户一注，截止后不可撤） |
| 2 小时异议昭示（跨夜顺延） | 截止后锁定待判定 → 判定录入进入 `dispute_window`（2 小时昭示，跨夜顺延）→ 到期自动结算 |
| 五维榜单 | 连胜榜 / 周榜 / 月榜 / 总积分榜 / PK 胜率榜 |
| 破产补助 | 爻归零后每日可领 500（可配置为分享或激励视频广告触发） |
| 双视图审核 | `APP_MODE=compliance` 时隐藏全部积分交互，仅剩民意问卷 |
| 词汇脱敏 | 全程使用「表态/支持率/爻/预言成功」等合规词汇（见 `constants.js` WORD_MAP） |

### 1.3 明确的非目标（一期不做）

- 不做真实货币充值、提现、兑换可变现实物（合规红线，永不触碰）；
- 不做 UGC 发题（仅官方运营发题）；
- 不做二级市场实时买卖（二期）；
- 不做用户间私下积分交易（发现即封禁，防止被认定开设赌场）。

  仲裁：createArbitration / getArbitration / voteArbitration / settleArbitration
  判定与结算：createMarket / resolver / resolveMarket / settleMarket / lockMarkets / getPendingReviews
  运营后台：getDataSources / upsertDataSource / getDashboardStats
  AI：aiDraftSpec / aiSuggestTopics
  系统：resetPeriods / rankSnapshot / rankHonors / adRewardCallback / migratePoints
        │
        ▼
云数据库：users / markets / bets / data_sources / resolution_logs / invites / pks / rank_snapshots / arbitrations / arbitration_votes（启用广告服务端回调时另加 ad_rewards）

事件选题、机读判定规范与三层自动判定的完整方案见 [事件选题与自动判定方案.md](事件选题与自动判定方案.md)。

- **本地 Mock 模式**：`config.USE_MOCK = true`（当前配置为 `false`，本地纯演示时临时改回 `true`），无需后端，数据存于本机 storage，含「开发者模拟结算面板」，可直接走通全流程；
- **云开发模式**（当前默认）：`config.USE_MOCK = false`，按第 5 节步骤开通环境、建集合、部署云函数。

## 3. 前端页面与交互设计

| 页面 | 路径 | 核心内容 |
| --- | --- | --- |
| 首页 | pages/index | 分类横滑（6 大类）、预言卡片流（标题/截止/双池/返还倍数）、分页加载更多 + 骨架屏、爻与连胜概览 |
| 详情 | pages/detail | 判定标准、实时瓜分池、方向选择、多档额度、已表态状态、判定结果、社区仲裁、开发者结算面板 |
| 榜单 | pages/leaderboard | 连胜/周/月/总/PK 胜率五维榜单，Top 3 奖牌，我的排名高亮 |
| 我的 | pages/profile | 爻/连胜/最高连胜、周月累计、预言记录入口、破产补助、邀请分享、规则说明 |
| 记录 | pages/history | 我的全部表态历史（状态、金额、结算返还） |

关键状态机（detail 页）：

```
未表态(open) ──确认支持──▶ 已表态(open)
open ──截止时间到──▶ locked（停止收注，等待判定）
locked ──自动/管理员判定──▶ dispute_window（2h 昭示，可发起社区仲裁）
dispute_window ──昭示到期/管理员结算──▶ resolved（展示结果与返还）
```

审核双视图：`config.APP_MODE = 'compliance'` 时，首页隐藏爻/池数据，详情页变为纯问卷（投票不入爻、不发奖励），其余页面保留但不展示积分。

页面全集：用户端 `index / detail / leaderboard / profile / history / task / shop（荣誉墙） / invite / pk / arbitration`，运营后台 `admin/index / sources / publish / review / dashboard / suggest / batch`。

## 4. 关键算法与业务规则

### 4.1 瓜分池公式

```
P_total = P_yes + P_no
O_yes = P_total / P_yes ，O_no = P_total / P_no
R_user = A_user / P_winner × P_total
```

实现约定：

- 结算在云函数 `settleMarket` 中完成，逐注计算；
- **向下取整**（`Math.floor`），避免超发，保证爻守恒；
- 池异常（总池为 0 或胜方池为 0）时**原路退回**全部投入，状态记为 `refunded`；
- 一人一场一注：`bets._id = openid_marketId` 保证唯一，`placeBet` 在事务内校验。

### 4.2 结算与仲裁闭环

0. 截止时间到：`lockMarkets`（每分钟）把市场置为 `locked`，停止收注并进入待判定；
1. `resolver` 自动判定（api/weather）或管理员调用 `resolveMarket` 录入官方结果（携带铁证链接），状态 → `dispute_window`，`disputeEndsAt = now + 2h`（若落在北京时间 00:00~10:00 顺延至当天 10:00）；
2. 昭示期内参与者可发起社区仲裁（`createArbitration`，锁定全额爻作保证金），市场状态 → `arbitration_window`；
3. 定时触发器每 10 分钟调用 `settleMarket`（无参）：批量结算「已过昭示期且无仲裁」的市场；
4. 仲裁昭示 24 小时：成立则判定翻转、不成立维持原判定；**仲裁结束即终局**，直接进入结算，不再重复昭示；无有效对赌时保证金全额退回。

### 4.3 连胜与榜单

- 结算时：正确方 `streak + 1` 并更新 `bestStreak`；错误方 `streak = 0`；
- 每场净收益（`payout - 投入本金`）同时累加 `weekPoints / monthPoints / totalPoints`；
- `resetPeriods` 定时触发器每周一/每月 1 日清零周/月积分；
- 榜单查询：`getLeaderboard` 按对应字段降序取 Top 50，并计算我的排名。

### 4.4 破产补助

- 条件：`points <= 0` 且距上次领取 ≥ 24 小时；
- 前置动作：默认直接领取；配置 `REWARDED_VIDEO_AD_UNIT_ID` 后先看激励视频；
- 额度 `RELIEF_POINTS = 500`，可在 config 中调整。

## 5. 接入云开发（从 Mock 到正式环境）

### 5.1 准备

1. 在 [微信公众平台](https://mp.weixin.qq.com) 注册小程序，拿到 **AppID**（云开发不支持游客 appid）；
2. 微信开发者工具导入本工程根目录（已配置 `miniprogramRoot` / `cloudfunctionRoot`）；
3. 将 `project.config.json` 中 `appid` 替换为真实 AppID；
4. 工具栏点击「云开发」→ 开通并创建环境，记录 **环境 ID**。

### 5.2 配置与部署

1. `miniprogram/utils/config.js`：
   - `USE_MOCK = false`；
   - `CLOUD_ENV = '你的环境ID'`；
   - `APP_MODE`：提审期间 `'compliance'`，运营期间 `'full'`；
   - `ADMIN_OPENIDS`：填入管理员 openid（云开发控制台 → 用户管理可查）。
2. 云开发控制台 → 数据库 → 依次创建 `database/design.md` 中的集合（users / markets / bets / data_sources / resolution_logs / invites / pks / rank_snapshots / arbitrations / arbitration_votes，启用广告服务端回调时另加 ad_rewards）；
3. `markets` 集合导入 `database/markets.seed.json`（详见 `database/design.md`）；
4. 开发者工具资源管理器右键 `cloudfunctions` 下每个函数目录 →「上传并部署：云端安装依赖」；
5. 确认定时触发器已随 `config.json` 部署（控制台「云函数 → 触发管理」可核对）：`lockMarkets`（每分钟）、`resolver` / `settleMarket`（每 10 分钟）、`settleArbitration`（每 5 分钟）、`rankSnapshot`（每天）、`resetPeriods`（每周/每月）、`myPks`（每 10 分钟）；
6. 按 `database/design.md` 的建议在控制台为集合添加索引。

> 部署小贴士：云函数修改后需重新「上传并部署」；`ADMIN_OPENIDS` 修改后同样需要重新部署对应函数。

## 9. 合规红线备忘（不可妥协）

1. 任何「法币充值 → 概率玩法 → 可变现产出」的闭环都是红线，**永不做**；
2. 爻仅单向发放，**严禁双向兑换**（含话费卡、黄金、高价值实物等变相形式）；
3. 主动监控并封禁「币商」：用户间折扣买卖积分的账号，一经发现永久封禁；
4. 积分消耗只能落在无 resale 价值的虚拟道具上；
5. 界面与宣传严格使用脱敏词汇，平台类目与提审素材保持「问卷/趣味测试」口径。
