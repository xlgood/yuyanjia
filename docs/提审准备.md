# 提审准备（微信小程序提审材料与自检）

> 目标：一次过审。预测类小程序类目审核较严，本清单覆盖提审前必须确认的技术与合规项。
> 状态更新：2026-08-12

## 一、提审模式决策（先定，影响页面表现）

| 模式 | 表现 | 适用 |
|------|------|------|
| `full`（当前） | 完整预言市场：能量/瓜分池/榜单/PK/仲裁 | 正常运营版 |
| `compliance` | 纯民意问卷：隐藏积分交互与「下注感」文案 | 审核受阻时的提审备选 |

- 开关位置：`miniprogram/utils/config.js` → `APP_MODE`
- 决策建议：**先以 `full` 提审**；若被驳回提示「预测/博彩」类风险，再切 `compliance` 重新提审（双视图就是为此准备的）
- ⚠️ 合规红线自查（README 五项硬性标准 + 词汇脱敏）：标题必须二值化、单一结算源、无政治/社会敏感、悬念区间 20%-80%；所有运营文案避免「下注/赔率/竞猜/庄家」等词（`constants.js` 的 `WORD_MAP` 是自查对照表）

## 三、订阅消息模板申请（公众平台 → 订阅消息）

申请 2 个模板，**字段类型/名称与代码严格一致**（代码用 `thing1/2/3`）：

**模板 1：判定结果通知**（settleMarket 使用，`SUBSCRIBE_JUDGE_TMPL`）
- 触发场景：表态的事件判定结果出炉结算后
- 字段（代码 `thing1/2/3`）：预言事件、判定结果、获得能量
- 提交时选「一次性订阅」；代码请求时机：详情页表态成功后 `subscribe.requestJudge()`

**模板 2：仲裁结果通知**（settleArbitration 使用，`SUBSCRIBE_ARBITRATION_TMPL`）
- 触发场景：参与仲裁结算后
- 字段（代码 `thing1/2`）：预言事件、仲裁结果
- 代码请求时机：发起仲裁成功后 `subscribe.requestArbitration()`

申请要点：关键词选「赛事通知/活动结果通知」等贴近预测的类目；模板内容避免出现「下注/奖金」等字样（用「能量/荣誉」）。

## 四、隐私保护指引（公众平台 → 设置 → 服务内容声明）

- [ ] 声明收集的信息：**昵称**（用户输入）、**微信头像/标识**（openid 登录）、**日志信息**（云函数调用）
- [ ] 声明用途：账号识别、参与活动、结果通知
- [ ] 小程序内：首次输入昵称前弹《用户隐私保护指引》同意框（可复用 `wx.showModal` 或隐私协议组件）
- [ ] 代码中涉及用户信息的 API 均在前端（无 getUserProfile/位置等强权限 API，风险低）

## 五、类目与资质注意

- [ ] 类目选择：优先「娱乐 - 其他」或「工具」；避免「博彩/抽奖」类目字眼
- [ ] 页面与文案自查：无「下注/投注/赔率/竞猜/返现/提现」；能量仅兑换虚拟荣誉（README 合规声明已覆盖）
- [ ] 若审核问询：备好「虚拟能量不可变现、无资金池、仲裁机制、内容安全双保险」的说明材料
